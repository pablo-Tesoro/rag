# Banco Olvessa — employee assistant (portfolio project)

> **Everything in this repository is fictitious.** Banco Olvessa does not exist; its
> policies, employees and operations are invented for demonstration purposes.

An agentic assistant for the employees of a fictitious Spanish bank, built with LangGraph:

1. **Policy questions** answered with RAG over internal documents, with validated citations
   and explicit abstention when the evidence does not answer the question.
2. **Operation lookups** in a simulated core-banking system, limited to the employee's
   office, with "not found" and "not allowed" indistinguishable.
3. **Incidents** opened only after a human approves them (LangGraph `interrupt()`), with an
   idempotent write.

The project is built to be defended in an interview: every decision has a written
rationale ([docs/decisiones.md](docs/decisiones.md), Spanish) and every number below comes
from a run saved in [`evals/results/`](evals/results).

How to read these numbers:

- The datasets are small on purpose (each case targets a known failure mode): one case is
  worth 0.05 of the dev pass rate per repeat and 0.10 of the test pass rate. Differences of
  one or two cases are indicative, not significant.
- pass^k counts the cases that pass in every one of k repeats: the agent is not
  deterministic, so consistency is measured rather than assumed.
- The judge is itself a model. It was checked against answers with known verdicts and every
  failure it reported on dev was reviewed by hand ([docs/progreso.md](docs/progreso.md)).
- The quality gate was fixed before the first run: every critical case (permissions,
  prompt injection, human approval) passes in every repeat, no run ends with an error, and
  the pass rate is at least 0.80.
- A perfect score on the 10 test cases means that none of them fails, not that the failure
  rate is zero; dev, with more multi-hop and abstention cases, is the more informative
  estimate.
- Retrieval with the raw question is a conservative bound: on test it misses the policy
  section for an operation question, which the agent finds after looking the operation up
  (its own evidence recall is complete).
- The bm25 ablation run is marked `-dirty` only because the dense run's results were not yet
  committed when it started; the code was that of `a207f86`. Results no longer count as
  changes (`evals/runinfo.py`).

## Architecture

```
POST /chat  ──  X-Employee-Id ──► Employee (office, groups): runtime context, never an LLM argument
   │
   ▼
LangGraph StateGraph  (checkpointed in Postgres: conversations and pending approvals survive restarts)
   agent ──► tools ──────────────► approval ──► agent ──► … ──► finalize
   (Gemini,   │ buscar_normativa      │ interrupt(): nothing      (structured answer,
    tools     │   hybrid retrieval:   │ is written before the      citations checked
    bound)    │   pgvector + BM25 in  │ human decides; then an     against what was
              │   SQL, fused with RRF │ idempotent insert          retrieved)
              │ consultar_operacion   │
              │   core banking, office filter in SQL
```

- **Retrieval** ([`retrieval/`](src/bank_assistant/retrieval)): dense search with
  `multilingual-e5-small` (local, CPU) in pgvector, BM25 implemented in SQL over an inverted
  index, and Reciprocal Rank Fusion. Permission and validity filters live in the same `WHERE`
  as the search, so a restricted chunk never reaches the model or the BM25 statistics.
- **Ingestion** ([`ingestion/`](src/bank_assistant/ingestion)): Markdown and PDF (tables
  stitched across pages) split by section into chunks measured with the embedding model's
  tokenizer; incremental by content hash.
- **Agent** ([`agent/graph.py`](src/bank_assistant/agent/graph.py)): an explicit four-node
  graph rather than a prebuilt agent, so validation, loop limits, timeouts, approval and the
  answer format each have one place and one test.
- **API** ([`api/app.py`](src/bank_assistant/api/app.py)): FastAPI with liveness and
  readiness probes; the service starts without an LLM key and reports why it is not ready.
  A provider rate limit or outage is answered with `503` and `Retry-After`, not a `500`.
- **Observability**: JSON logs without personal data or free text; optional LangSmith traces
  with identifiers masked before they leave the process
  ([`tracing.py`](src/bank_assistant/tracing.py)).

## Security invariants

| Invariant | Where it is enforced | How it is checked |
|---|---|---|
| Permission and validity filters are applied in the database query, never in the prompt | `retrieval/retriever.py`, `core_banking/repository.py` | Integration tests; permission cases with forbidden documents and strings |
| The employee identity comes from the request context, never from tool arguments | `AgentContext`; tool schemas forbid extra fields | Unit tests |
| "Not found" and "not allowed" return the same answer | `agent/tools.py` | Unit tests; operation cases |
| Retrieved content is delimited and escaped, and treated as data | `agent/tools.py`, system prompt | Prompt-injection cases with a canary string and a forbidden incident |
| Writes require human approval and are idempotent | `approval` node, idempotency key | Crash-and-replay test; approval cases count incidents before and after |
| Logs carry no personal data; employee ids are HMAC pseudonyms | `logs.py` | Unit tests |
| Traces mask identifiers before upload | `tracing.py` | Test against a fake LangSmith endpoint |
| No secret is committed | `.env.example` | Test that every credential in it is empty |

## Quickstart

Requirements: Docker and make, and a free Gemini API key from Google AI Studio.

```bash
cp .env.example .env          # then set GOOGLE_API_KEY in .env (never commit it)
make up                       # builds the image, starts Postgres + API, waits until healthy
make ingest                   # loads the fictitious corpus and core-banking data
curl -s localhost:8000/readyz
curl -s -X POST localhost:8000/chat -H 'Content-Type: application/json' \
     -H 'X-Employee-Id: EMP-001' \
     -d '{"message": "¿Cuál es el límite diario de una transferencia inmediata en oficina?"}'
```

A proposed incident comes back as `pending_approval`; approve or reject it with
`POST /chat/{thread_id}/approval` and `{"approved": true}`.

`make demo` walks through every technique against the running API (permissions, the
obsolete policy, the planted prompt injection, abstention, approval and rejection), narrated
in Spanish, and saves what it saw to [`docs/demo/transcript.json`](docs/demo/transcript.json).
It makes about 30 LLM calls.

Development (Python 3.12 and [uv](https://docs.astral.sh/uv/)):

```bash
make setup             # dependencies and .env
make check             # ruff, mypy (strict) and pytest; integration tests use the compose Postgres
make ingest-local      # load the data with the local environment
make eval-retrieval    # recall@5 and MRR per retrieval mode, no LLM calls, with a regression gate
make eval-judge        # the LLM judge against answers whose verdict is known
make eval ARGS="--repeat 3"   # agent evaluation on dev with the quality gate (uses LLM quota)
make eval-ablation     # agent evaluation on dev for each retrieval mode
```

CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs the deterministic checks on
every pull request: lint, types and tests against Postgres, the retrieval regression gate
with the real embedding model, and a Docker build that starts the stack and ingests inside
it. The agent evaluation spends free-tier quota, so it runs on demand
([`eval.yml`](.github/workflows/eval.yml)).

## Evaluation

The dataset ([`evals/dataset.jsonl`](evals/dataset.jsonl)) has nine categories, each tied to
a deliberate trap in the corpus ([`data/README.md`](data/README.md)): near-identical product
codes, an obsolete policy next to the current one, restricted documents and public documents
that refer to them, a planted prompt injection, cross-references across documents, a table
split across PDF pages, operations of other offices and incidents that must wait for
approval. Labels point to `(document, section)`, never to chunks, so they survive chunking
changes. Details of the checks, the judge and the gate are in
[`evals/README.md`](evals/README.md).

## Key decisions

All of them, with alternatives and trade-offs, are in [docs/decisiones.md](docs/decisiones.md)
(Spanish). The ones most worth discussing:

- **Free LLM behind `init_chat_model`** (D-02): Gemini's free tier, replaceable by
  configuration; the evaluation design (rate limiters, repeats, which runs to spend quota on)
  is shaped by its quotas (D-32).
- **BM25 in SQL** (D-12) and **RRF** (D-13): one transactional source of truth, filters in the
  same query as the search; it would not scale to millions of documents.
- **Explicit graph** (D-18), **structured final answer as a tool** (D-19) and **citations
  validated by code** (D-20, revised in D-33).
- **Approval before an idempotent write** (D-21) and **identity in the runtime context**
  (D-22).
- **Code checks first, judge only for correctness and groundedness**, with binary verdicts
  per key fact and negative controls for the judge (D-30).
- **Pre-registered experiments**: the quality gate (D-31), the prompt change (D-33) and this
  final ablation and test run (D-36) were written down before running them.
- **Traces masked at the source** (D-34) and **CI that never spends LLM quota** (D-35).

## Limitations

- The datasets and the corpus are small (13 documents, 30 cases): enough to exercise each
  failure mode, not to estimate rates precisely.
- The judge (`gemini-3.1-flash-lite`) is not stronger than the agent, because the free tier
  gives the stronger model too few requests per day. Its controls only cover clear-cut errors.
- The ablation ran each alternative retrieval mode once, against three repeats for hybrid.
- There is no real authentication: the employee header is trusted. In production it would be
  a verified token; the rest of the design (delegated identity, filters in the query) would
  not change.
- Trace masking is regex-based: it catches known identifier formats, not free-text names.
- Exact vector search and per-query BM25 statistics fit this corpus, not a large one.
- Only Gemini has been run; other providers are a configuration change that has not been
  evaluated. PDFs are born-digital: there is no OCR.
- The on-demand evaluation workflow has not run yet: it needs the API key as a repository
  secret on the default branch.
